# Gorgon — face-animation chunk streaming

Streaming pipeline for lip-sync / facial-animation chunks from a TTS+face model
to a browser avatar over WebSocket, built around a strict binary wire contract
(**facecontract v1.4.1**, magic `GRG1`).

```
face model ──chunks──▶ UtteranceStateMachine ──▶ SessionStateMachine ──▶ Gorgon (glue)
   VAD events ──────────────▶  (IDLE / BUFFERING /     (owns seq, t_ns,      (peek → encode →
                               SPEAKING / HANGOVER)     queue, backpressure)  commit → wire frame)
```

Everything in this repository is **locked and verified by real runs**: the
self-test prints identical CRCs across runs (determinism gate), 40 Python unit
tests pass, an independent JS decoder re-verified all 22 frames (16 session +
6-chunk speech_to_idle stream), and a behavior test validates the OEF tuning
and the §7.2 crossfade gate.

## Quick start

```bash
# 1. Determinism gate: 5 canonical vectors, CRCs must be identical every run
python facecontract_v141.py

# 2. Get the raw .fc14 conformance vectors — either restore the stored
#    base64 copies or regenerate them deterministically (byte-identical)
python test_vectors/decode_b64.py
python facecontract_v141.py --vectors   # equivalent alternative

# 3. Python test suite (40 tests)
python -m unittest test_facecontract_wire test_gorgon_glue test_gorgon_edge -v

# 4. Independent JS conformance (no deps, CRC-32 implemented from scratch)
node verify.js

# 5. Client-side OEF behavior thresholds
node verify_behavior.mjs
```

Expected canonical CRCs (the determinism gate):
`minimal_idle=0x8E1099E7`, `speech_bs4=0x38966E08`, `hangover_tail=0x7EC8DA2F`,
`extreme_values=0x75CE3EEC`, `bs8_chunk1=0x23A861E5`.

## Wire format in one screen

32-byte little-endian header, then payload, then CRC-32 (IEEE, zlib poly
`0xEDB88320`) over `[0, 32+N)`:

| offset | size | field |
|---|---|---|
| 0 | 4 | magic `"GRG1"` |
| 4 | 1 | version_major = 1 |
| 5 | 1 | version_minor = 4 |
| 6 | 1 | flags — one-hot: `FLAG_IDLE=0x01` / `FLAG_SPEAKING=0x02` (I3) |
| 7 | 1 | bs_count ∈ {1,2,4,8,32,52,72} (I6) |
| 8 | 2 | fps |
| 10 | 2 | chunk_size |
| 12 | 4 | seq — u32, strict +1 per emitted frame (I1) |
| 16 | 4 | dur_us — **advisory only**, floor of dur_ns |
| 20 | 4 | payload_len N — validated **before** CRC (defence-in-depth) |
| 24 | 8 | t_ns — u64, **ground truth for pacing**, strict step (I2/I9) |
| 32 | N | payload, N/4 float32 LE, N = bs_count × chunk_size × 4 |
| 32+N | 4 | crc32 over `[0, 32+N)` |

Key protocol decisions (details in `PROTOCOL.md`):

- **`t_ns` is ground truth.** `dur_us = 133333` is the advisory floor of the
  real step `dur_ns = chunk_size·10⁹/fps = 133333333 ns`; clients MUST pace by
  `t_ns[i+1] − t_ns[i]` (a naive `dur_us·1000` drifts ~9 ms/hour, ~1.5 s/week).
- **CRC residue invariant:** for any valid frame, `crc32(frame_with_crc)` is
  the constant `0x2144DF1C` (LE CRC store) — a free structural check on every
  frame, independent of content.
- **`payload_len` is checked before the CRC** — a corrupted length or a
  truncated frame produces a specific error even with a broken CRC field.
- **Reconnect = new session:** seq restarts at 0 with a fresh `t_ns` epoch;
  the queue is not inherited. Clients fade-in on the first frames.
- **Hold-last tail in HANGOVER:** after `model_done` the last speech payload
  is held; late model chunks are rejected and can never resurrect the tail.

## Integration sketch

```python
from gorgon_state import GorgonConfig
from gorgon_glue import Gorgon

cfg = GorgonConfig()            # fps=30, chunk_size=4, hangover_ms=500, max_queue_depth=8
g = Gorgon(cfg, bs_count=4, idle_gen=my_idle_gen, model_queue=my_queue)

g.on_ws_open(start_t_ns=0)      # per-WebSocket session: seq=0, t_ns epoch
# ... on_vad_start / on_model_chunk / on_vad_end / on_model_done from adapters ...
g.tick(now_us)                  # once per chunk period (≈133.33 ms)
frame = g.take_frame()          # bytes ready for ws.send(), or None
```

`Gorgon` never drops speech (I7/I8), never emits half-chunks, and shifts
`seq`/`t_ns` in exactly one place — `SessionStateMachine.commit()` — which
runs only after a successful `encode()`, so an encode failure cannot create a
sequence gap.

## Invariants (locked)

| ID | Invariant |
|---|---|
| I1 | `seq` strictly +1 within a session |
| I2 / I9 | `t_ns` strict step = `chunk_size·10⁹/fps`, monotone |
| I3 | flags exactly one of IDLE / SPEAKING |
| I4 | CRC-32 valid on every frame; residue `0x2144DF1C` |
| I5 | seq = 0 on every new WebSocket session |
| I6 | bs_count ∈ {1,2,4,8,32,52,72} |
| I7 | no speech chunk dropped while utterance is live |
| I8 | no half-chunks / partial payloads on the wire |
